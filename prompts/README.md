# Prompt 模板库

这个目录不是"提示词收藏夹"，是一份**契约清单**：每份模板都规定了下游代码能接受什么、必须拒绝什么。
模板和 `guard-go` / `guard-java` 里的校验规则是一体的——模板负责"让 AI 少犯错"，校验负责"兜住它还是会犯的错"。只有前者是赌博，只有后者是内耗。

---

## 一、模板格式：固定五段，顺序不变

任何一份模板都必须有这五段。少一段就不是模板，是许愿。

| 段 | 写什么 | 反例（为什么不行） |
|---|---|---|
| **1. 目标** | 一句话说清产出物是什么、给谁用 | "帮我分析一下这个证照" —— 分析成什么？给谁看？ |
| **2. 范围** | 只处理哪些输入，其余一律返回什么 | 不写范围，模型就会替你扩展任务边界 |
| **3. 禁止动作** | 明确列出"不许做什么" | 这是最容易被省掉、也最容易被 AI 钻空子的一段 |
| **4. 输出格式** | 字段、类型、枚举、长度，越死越好 | "用 JSON 返回" —— 模型会自己发明字段名 |
| **5. 验收标准** | 什么样的输出算合格，不合格怎么办 | 没有验收标准，模型就默认"能返回就算成功" |

**结构上的取舍：**

- 段与段之间用 `##` 分隔而不是自然语言过渡。模型对结构化标记的服从度显著高于散文。
- 「禁止动作」放在「输出格式」**之前**。先划禁区，再定格式——顺序反了，模型会先按格式编内容，再绕着禁区打补丁。
- 所有模板段落用**陈述句 + 编号**，不用"请""麻烦""尽量"。语气词会稀释约束力。

## 二、版本化：文件名带 `vN`，正文顶部带变更块

```
item-extract.v1.md
license-verify.v1.md
```

改动规则（三条，写死）：

1. **只加不删**：新增字段/新增禁止项 → 升小版本（v1 → v1.1），老调用方不用改。
2. **改语义必升大版本**：字段含义变了、枚举值变了 → v2，老版本保留至少一个迭代周期。
3. **每次改动必须在文件顶部写变更块**：改了什么、为什么改、对应哪条真实事故。

第 3 条不是流程洁癖。**没有变更块的模板，出问题时无法回溯是"提示词退化"还是"模型换版本"。** 我踩过这个坑：同一个 prompt 在模型小版本升级后开始把过期证判成有效，因为没有版本记录，查了两天才确认不是代码问题。

## 三、为什么"禁止动作"这一段是核心

AI 的错误不是随机噪声，是**倾向于把任务做完**。你说"判断这个证是否有效"，它就会想尽办法给出一个结论，哪怕信息不足。

「禁止动作」的作用是把"我不知道"变成一个**允许且被期望的**输出。例如：

```
禁止：在未提供 verificationDate 的情况下，根据图片调用时间、发证日期或训练数据推断"今天"是哪天。
禁止：证据不足时给出 PASS/FAIL，必须返回 UNKNOWN 并在 missingEvidence 中说明缺什么。
```

第二句是关键：**不只告诉它不许做什么，还要给它一条合法的退路。** 只堵不疏，模型会绕过去编一个更隐蔽的错。

## 四、模板与校验规则的对应关系

| 模板 | 主要约束 | 对应的校验规则（reasonCode） |
|---|---|---|
| `item-extract.v1.md` | 只输出请求清单内的 itemId、四字段、枚举结论 | `E_ITEM_NOT_REQUESTED`、`E_RESULT_NOT_ENUM`、`E_CONF_CONFLICT` |
| `license-verify.v1.md` | 必须用 verificationDate 判断有效期、证据必须逐字摘录 | `E_EVIDENCE_NOT_FOUND`、`E_EVIDENCE_TOO_SHORT`、`E_LOW_CONFIDENCE` |
| 两者共同 | 不许补全、不许推测缺项 | `E_ITEM_MISSING`、`E_TRUNCATED` |

**这张表的意义：** 任何一条校验规则，都必须能追溯到某份模板里的某一句约束。追溯不到的规则说明是凭感觉加的，该删；没有对应规则的约束说明只是口号，该补。

## 五、使用方式

模板不是给人读的文档，是被代码读的字符串。建议的接法是：

1. 模板文件按 `prompts/<name>.vN.md` 存放，构建时打进资源目录。
2. 调用层用 `prompts/<name>.vN.md` 的**文件名**作为版本号写进日志和 traceId，出问题能定位到具体版本。
3. 模型返回后**先过 `guard`，再落库**。顺序不能反：任何"先存下来后面再校验"的方案，最后都会变成"脏数据已经在那儿了"。

## 六、这个目录里有什么

- `item-extract.v1.md` —— 检查项结构化抽取（把现场记录拆成 N 条结构化结论）
- `license-verify.v1.md` —— 证照有效期核验（含最典型的时间锚点事故的防法）
- `failure-cases.md` —— 10 类真实失败案例，每条都标注了拦截点和对应的 reasonCode

`failure-cases.md` 是这里最该先读的一份。模板是从事故里长出来的，不是反过来。
