# 03 · 三天上手路线（你自己要亲手走一遍的部分）

> **先说清楚一件事。**
> 这个仓库的代码是我（代理人）替你搭的。它的作用是**给你一个正确的参照物和一套可跑的断言**，
> 让你在两天内能独立复现出等价的结果，而不是让你拿着它去说"我写的"。
>
> 面试官只要问三层：为什么阈值是 0.90 / 为什么 UNKNOWN 豁免证据 / 全角空格那个坑怎么发现的。
> **没亲手改过代码的人，第三层必挂。** 下面每一天都标了"你必须亲手做的事"。

## D0（30 分钟）· 先把它跑起来

```powershell
# Go 侧
cd D:\studySpace\ai-delivery-guard\guard-go
$env:GOTOOLCHAIN="local"
D:\soft\go-sdk\go\bin\go.exe test ./... -v
D:\soft\go-sdk\go\bin\go.exe run . -selfcheck

# Java 侧
cd D:\studySpace\ai-delivery-guard\guard-java
.\run.bat
```

要看到的结果：

- Go：`ok ... guard`，18 个用例全 PASS
- Java：`自测结果：17/17 通过`，接着打印一份 demo JSON
- 两边 demo 输出的 JSON 字段应该完全一致

**这一步不要做别的**，先确认环境通。Go 用的是解压在 `D:\soft\go-sdk\go` 的 1.23.4，不污染系统 PATH；如果要用 `go` 命令，把它加进 PATH。

> 顺手记一件事：`go run . -selfcheck` 是**不启服务、直接看结果**的模式。面试现场演示时用这个，比 `curl` 快得多，也不会因为端口被占而尴尬。

## D1（3 小时）· 亲手重写 Go 版，不许看现有代码

这是整条路线里最重要的一天。做法：

1. 把 `guard-go/guard/engine.go` **改名藏起来**（比如改成 `engine.go.bak`），只保留 `engine_test.go`。
2. 对着测试用例，自己写 `engine.go`，直到 `go test ./...` 全绿。
3. 写不出来的地方，**先问 AI**，但要求它「只解释这条测试在断言什么，不要给我完整代码」。
4. 卡住超过 15 分钟再看 `.bak`。

**为什么要做这一步：**

- 你会真实地遇到 Go 的语法障碍（接口、指针、错误处理、`strings.Builder`），这些是面试时"你写过 Go 吗"的答案。
- 你会真实地体会到"读断言 vs 读实现"的差别（见 `docs/02` 第四节第 2 步）。
- 全绿的那一刻，你说"我用两天把一套 Java 规则迁到 Go"就是有底气的。

**你必须亲手做的事：至少自己写出一遍 `checkOne` 和 `Normalize`。** 这两个函数包含了这个项目 80% 的语言细节。

**验收：** 不看原文件，能白板写出 `Normalize` 的 Java 版和 Go 版，并说清 `U+3000` 的差别。

## D2（3 小时）· 改一条规则，加三条测试

只跑通别人的代码，不叫上手。**能改，才叫上手。**

选一个改（任选其一）：

**选项 A：把置信度阈值改成可配置，并加一条"阈值从配置读不到时用保守值"的测试**
→ 练的是：配置读取、默认值策略、fail-closed

**选项 B：加一条新规则 G8「`evidence` 必须是连续片段，不能被省略号截断」**
→ 练的是：加规则要同步改哪几个地方（model 常量、engine、两套测试、文档表格）

**选项 C：把 `Result` 从 string 改成枚举类型（Go 的 `type Result string` + 常量）**
→ 练的是：Go 没有 Java 的 enum，怎么用自定义类型 + 方法模拟

做完必须同步更新：

- [ ] `guard-go` 和 `guard-java` **两边都改**（这是等价性检验，只改一边等于放弃了这个项目的核心价值）
- [ ] 两边测试全绿
- [ ] `prompts/README.md` 的对应关系表里加上新规则的追溯
- [ ] `Prompts/failure-cases.md` 的表格里加上一行

**验收：** 能用一句话说清"加一条规则要动 5 个地方，漏一个就会不一致"。

## D3（2 小时）· 接到真实场景 + 收口

### 1. 把门禁接到你真实做过的业务里（30 分钟）

在 `README.md` 里补一节，写清楚：

- 你在真实项目里，这套规则对应哪个模块的哪一段代码（`supervisecheck-ai` 里的核验链路）
- 真实的 `sourceText` 是什么（现场检查记录），真实的 `itemId` 长什么样（`1.1`、`2.2`）
- 当时的拦截结果是：**多少项被丢、丢的原因分布是什么**

**这段内容别人抄不走，因为它来自你的真实项目。**

### 2. 录一遍（30 分钟）

对着屏幕讲三遍，每遍 3 分钟：

> "这是一个 AI 输出的质量门禁。起因是我在政务项目里发现模型会把过期证判成有效、会在证据不足时硬给结论、会返回不存在的检查项——而且这些错误**没有一条会抛异常**。
>
> 我做的是把 8 条判定规则做成两个语言的等价实现，Java 作为语义基准，Go 是我用两天迁过去的。17 条断言在两边跑，输出逐字段一致。
>
> 这里有几个设计取舍能说明问题：`UNKNOWN` 豁免置信度和证据——否则模型诚实地说'我不确定'反而被门禁打死；冲突结论整项丢弃而不是择一——因为选哪条都是赌博；证据只做格式归一化不做模糊匹配——放过一条编造的证据，整批结论就归零了。"

录音回听，重点听**有没有背课文的感觉**。有，就再讲一遍，直到像在说一件自己做过的事。

### 3. 边界清单（30 分钟）

写一页纸，回答三个问题：

- 这个项目**没做**什么？（评测集、自动修正、RAG）
- 哪条规则是**有争议**的？（`MIN_CONFIDENCE=0.90` 是我按"结论性输出"定的，如果只做辅助提示该降到 0.75）
- 如果重做一遍，**先做什么**？（先把断言集写出来，再写实现——这次是反过来的）

**面试被问"有什么不足"时，直接念这一页。** 主动交底是信任加速器，前提是交得具体。

## 红线：没做过就别说的话

| 不能说 | 原因 | 替代说法 |
|---|---|---|
| "我用 Go 开发了生产服务" | 你没上过生产 | "我用两天把一套规则迁移到 Go，17 条断言全绿，有仓库可看" |
| "这个项目提升了准确率" | 没评测集，无从谈起 | "它提升的是可用数据的可信度，代价是可用数量下降" |
| "我做过 RAG / Agent 编排" | 这个仓库没有 | 说 `supervisecheck-ai` 里的结构化工具调用和两步式链路 |
| "8 条规则都是我总结的" | 部分是站在现有实践上 | "从我自己踩的 10 个坑里倒推出来的，其中 8 条有可跑测试" |
| "TDD" | 不是 TDD | "先写代码后补测试。如果重做，会先写验收标准" |

**唯一不能碰的是"编"。** 这个岗位的面试官就是不按标准筛人的那一批，他们的判断力比你强，编一句就废全局。

## 面试前 10 分钟看这个

```
一句话定位：AI 输出的质量门禁，8 条规则，Java/Go 双实现，17 条断言逐字段一致。

三个设计取舍：
  1. UNKNOWN 豁免证据与置信度 —— 否则诚实被罚，模型会去编
  2. 冲突整项丢弃不择一 —— 两条都 0.95 时选哪条都是赌博，交给人
  3. 证据只做格式归一化 —— 放过一条编造的证据，整批归零

两个坑：
  1. Java 的 Character.isWhitespace(U+3000) 是 false，Go 的 unicode.IsSpace 包含它
  2. HttpServer 不设 executor 就是串行，功能测试全过、压测 QPS 卡在个位数

三个边界：
  1. 不解决"判断是否正确"，只解决"形式与自洽"
  2. 没做评测集，这是欠账
  3. 不自动修正，只拒绝并说明原因
```
